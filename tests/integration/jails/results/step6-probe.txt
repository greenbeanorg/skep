== probe2/probe3: the build jail and `jexec -l -U root` ==

Jail: jail -c name=skep-build-probe path=<root> persist ip4=disable
ip6=disable enforce_statfs=2 children.max=0 securelevel=2 exec.clean, every
allow.* the kernel lists set to 0 (set_hostname, sysvipc, raw_sockets,
chflags, mount, quotas, socket_af, mlock, reserved_ports, read_msgbuf,
unprivileged_proc_debug, unprivileged_parent_tampering, suser, nfsd,
extattr, adjtime, settime, routing, setaudit), no mount.devfs.
jail -c exit 0. jail -r exit 0; jls -j afterwards: "not found" (exit 1).

Before pwd.db exists:
  jexec -l -U root J /usr/sbin/certctl rehash -> jexec: getpwnam: root: No such file or directory  (exit 1)
  jexec -U root J ...                          -> same                                            (exit 1)
  jexec -l J ...                               -> exit 0
  jexec J ...                                  -> exit 0

FreeBSD's "files" passwd backend reads only pwd.db/spwd.db, never
master.passwd, and the template has no pwd.db until pwd_mkdb has run. So
the first two commands of the fixed order cannot start as specified.

After pwd_mkdb (run with `jexec -l`, no -U):
  jexec -l -U root J <anything> -> jexec: initgroups: root: Operation not permitted  (exit 1)

With allow.suser=0 (an allow.* parameter, so off under item 2) root in the
jail has no privilege, and jexec's initgroups()/setgroups() for -U needs
it. So -U root fails for every command, not only the first two, as long as
every allow.* is off.

`jexec -l` without -U gives, as uid 0 gid 0 (groups wheel, operator, the
caller's), this environment (root's login class):
  SHELL=/bin/sh HOME=/root USER=root BLOCKSIZE=K MAIL=/var/mail/root
  MM_CHARSET=UTF-8 LANG=C.UTF-8 TERM=su
  PATH=/sbin:/bin:/usr/sbin:/usr/bin:/usr/local/sbin:/usr/local/bin:/root/bin

== probe5/probe6: why services.db differs ==

services_mkdb is deterministic; the difference is its input.

  ba71f56b...  services_mkdb ... -o x /etc/services   in the jail, twice (identical)
  06eebad8...  services_mkdb ... -o x /               in the jail (the package form, PKG_ROOTDIR empty)
  06eebad8...  /usr/sbin/services_mkdb ... -o x <root>/   on the host, twice (the trace's form)
  06eebad8...  skeptest/trace-7b/root/var/db/services.db
  06eebad8...  hearst's own /var/db/services.db (installed 2026-10-21 by pkgbase)
  <root>/etc/services is identical to the trace's; it has 1928 service lines.

  Non-zero bytes: trace's services.db 285, hearst's own 285, the /etc/services
  build 225517. cmp: 225232 bytes differ, and the trace's byte is 0 in each
  sampled one.

The FreeBSD-runtime 15.1p6 post-install script passes `${PKG_ROOTDIR}/`, a
directory, as services_mkdb's input file. services_mkdb reads no entries
from it and writes an empty database (the header, preallocated). The traced
template and hearst's own base system both have that empty services.db. The
ADR's command (/etc/services) builds the populated one. So item 3's check
("identical to the one the traced build produced") cannot pass, and the
reason is a bug in the package script, not in Skep's command.

== Options (for Andy) ==

Problem 1 and 2: how the build commands enter the jail.

  A. Every command as `/usr/sbin/jexec -l skep-build-<id> <cmd>` (no -U),
     with every allow.* off including allow.suser, in the ADR's order.
     Verified above (probe4 a). The command runs with the agent's own
     credentials, uid 0 gid 0, which are what -U root would give, and gets
     root's login-class environment from -l. In a jail with allow.suser=0
     that root has no privilege beyond owning the files, which is all
     these commands need. Strictest of the three, and one uniform form.
     RECOMMENDED.
  B. allow.suser=1 in the build jail; pwd_mkdb first as `jexec -l` (no -U),
     then every command as `jexec -l -U root`. Verified (probe4 b). Keeps
     -U root for most commands, but gives jail root its privileges back and
     needs two invocation forms and a reordered or repeated pwd_mkdb.
  C. allow.suser=1 and `jexec -l -u root` (-u looks the user up on the HOST,
     so no pwd.db is needed in the jail). Not tested. Same privilege cost
     as B; mixes host and jail user databases.

  Related, for step 7: Decision 9's baseline says "every allow.* off" for
  ordinary jails too. allow.suser is an allow.* parameter, and with it off
  root inside a jail is unprivileged, so /etc/rc and most services will not
  work. Step 7 will need allow.suser=1 (the default) stated as an exception,
  or the baseline worded as "every allow.* that grants more than the
  default jail confinement off".

Problem 3: services.db.

  i.  Keep the ADR's command (/etc/services): the template gets a populated
      services.db; it differs from the package's (empty) output on purpose,
      and the comparison item records why. RECOMMENDED.
  ii. Mimic the package exactly (input "/"): the template gets the same
      empty database pkgbase gives a host. Bug-compatible, no value.
  Optionally, report the script bug upstream (outward action: Andy's call).

== Answers (Andy, 2026-11-16) and the lookup check ==

Option A; services_mkdb keeps /etc/services; Decision 9 amended (amendment
e: ordinary jails keep allow.suser on). Recorded in ADR 0010, step 6,
"Resolved". skeptest/step6-probe destroyed (zfs destroy exit 0).

Does hearst's own empty /var/db/services.db break name lookups? (read-only)
  getent services ssh     -> ssh                  22/tcp   (exit 0)
  getent services domain  -> domain               53/tcp   (exit 0)
  getent services 22      -> ssh                  22/tcp   (exit 0)
  /etc/nsswitch.conf: services: compat / services_compat: nis
No. In lib/libc/net/getservent.c (releng/15.1), the files and compat
sources fopen(_PATH_SERVICES) (/etc/services text); only the db source
dbopen()s _PATH_SERVICES_DB. With "services: compat" the db is never read.
A host configured with "services: db" would get no answers.
