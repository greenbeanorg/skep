ADR 0010 phase 7b, step 6: how `pkg --rootdir` runs package scripts and
triggers, and whether a pkgbase build changes the host. Recorded 2026-11-16
on hearst (FreeBSD 15.1-RELEASE-p6, amd64, pkg 2.9.2, pkgbase host, RACCT on).

This is the evidence the "scripts and triggers are verified, not assumed" rule
of Decision 7a (amendment a) asks for. It was a hand-run build into a scratch
dataset (skeptest/trace-7b, outside skeptest/skep), not a Skep task: Skep has
no template code yet. Scripts: ../pkgbase-trace.sh (as run) and
../pkgbase-trace-analyze.sh.

== 1. What the pkg 2.9.2 source says (freebsd/pkg tag 2.9.2, libpkg/) ==

- Shell scripts (pre/post-install/deinstall), scripts.c pkg_script_run():
  posix_spawn(_PATH_BSHELL) on the HOST. No chroot. Environment: pkg's own
  environ plus PKG_NAME, PKG_PREFIX, PKG_ROOTDIR=<rootdir>, PKG_MSGFD,
  PKG_UPGRADE when upgrading. Gated only by the RUN_SCRIPTS option
  (default true).
- Lua package scripts, lua_scripts.c: fork() on the host, no chroot.
  io.open/os.remove/os.rename are replaced by openat/unlinkat/renameat on
  rootfd (relative, no O_RESOLVE_BENEATH); pkg.exec/pkg.exec_capture spawn
  host binaries (posix_spawnp).
- Lua triggers, triggers.c: under --rootdir pkg_set_rootdir() sets
  ctx.defer_triggers = true, and trigger_execute_lua_common() then SAVES
  every trigger declared `sandbox: false` into <PKG_DBDIR>/triggers/ to be
  run later by `pkg triggers` inside the target, instead of running it.
  Sandboxed triggers (the default) run forked, after cap_enter() (Capsicum).
- Paths under --rootdir, pkg_config.c: every absolute string default is
  prefixed with the rootdir (pkg.conf, PKG_DBDIR, PKG_CACHEDIR); REPOS_DIR is
  an array and is NOT prefixed, so the host's repository configuration is
  used. Values given with -o are taken as they are (host-absolute).
- Trust anchors, pkg_repo.c pkg_repo_load_fingerprints_from_path(): the
  fingerprints directory is looked up INSIDE the rootdir first, and on the
  host only if absent there. Safe for Skep only because a template root is
  always a directory Skep has just created empty.

== 2. Which scripts the minimal set has (hearst's installed package DB) ==

FreeBSD-set-minimal and its dependencies (53 in the host's DB, 66 from the
repository): three packages carry scripts, all shell, none Lua.

FreeBSD-utilities  post-install   cap_mkdb -l ${PKG_ROOTDIR}/etc/login.conf

One trigger: /usr/share/pkg/triggers/mandoc.ucl (FreeBSD-mandoc), sandbox:
false, which runs pkg.exec({"/usr/bin/makewhatis", "/usr/share/man"}), a host
path if it ran on the host. Under --rootdir it is deferred (section 1).

== 3. The traced build ==

Command (inside ktrace -i -t cn, so every child is traced):

  env -i PATH=/sbin:/bin:/usr/sbin:/usr/bin ASSUME_ALWAYS_YES=yes \
    /usr/sbin/pkg --rootdir /skeptest/trace-7b/root \
      -o PKG_CACHEDIR=/skeptest/trace-7b/work/cache \
      -o PKG_DBDIR=/skeptest/trace-7b/root/var/db/pkg \
      install -y FreeBSD-set-minimal

/skeptest/trace-7b is root:wheel 0700 (the template-parent rule of Decision 9).
Outbound HTTPS to pkg.FreeBSD.org worked (hearst change 6); Pi-hole did not
block it.

Result: pkg exit 0; 66 packages; the root is 126M, the work-area cache 37M
(outside the root); `chroot <root> freebsd-version -u` = 15.1-RELEASE-p6,
equal to the host's kernel and userland. The scripts' outputs exist in the
root: etc/pwd.db, etc/spwd.db (0600), var/db/services.db, etc/login.conf.db,
118 entries in etc/ssl/certs.

Host state (Decision 16, "template host safety"): before and after, for every

== 5. Reading of the trace ==

- Exec chain: env -> /usr/sbin/pkg (the bootstrap) -> /usr/local/sbin/pkg
  (the host's pkg 2.9.2 from ports). Three /bin/sh children, which exec the
  HOST's /usr/sbin/certctl, /usr/sbin/pwd_mkdb, /usr/sbin/services_mkdb,
  /usr/bin/cap_mkdb (found through PATH). Nothing ran chrooted.
- The scripts read host files: the host's libraries and ld-elf hints,
  /etc/libmap.conf, /etc/malloc.conf, /etc/nsswitch.conf and /etc/shells
  (pwd_mkdb), /etc/ssl/openssl.cnf (certctl). They wrote only under the root:
  certctl opened <root>/etc/ssl/{certs,untrusted} and wrote through that
  descriptor; the mkdb tools were given <root> paths as arguments.
- pkg's own writes: relative to its root descriptor (the template), plus
  its repository-catalogue download temporaries in the HOST's /tmp
  (/tmp/meta.conf.*, /tmp/data.*, /tmp/files.*), each created and unlinked.
  TMPDIR was not set; the build should set it to the work area.
- The mandoc trigger was "run" (==> Running trigger: mandoc.ucl) as a deferred
  save: <root>/var/db/pkg/triggers/<random> holds it, to run on the first
  `pkg triggers` inside the jail. makewhatis never ran on the host.
- The environment of a script child (procstat -e of cap_mkdb, the only one
  the 0.2 s sampler caught; the others ended between samples):
    PKG_CACHEDIR=... PKG_DBDIR=... POSIXLY_CORRECT=1 ASSUME_ALWAYS_YES=yes
    PKG_PREFIX=/ PATH=/sbin:/bin:/usr/sbin:/usr/bin PKG_NAME=FreeBSD-utilities
    HTTP_USER_AGENT=pkg/2.9.2 PWD=/skeptest/trace-7b/root
    PKG_ROOTDIR=/skeptest/trace-7b/root PKG_MSGFD=4
  i.e. only the two fixed values given to env -i plus what pkg itself adds.
- var/cache/pkg does not exist in the root (the cache was in the work area).
  The root does hold var/db/pkg/repos/ with the catalogues of all three host
  repositories (FreeBSD-ports included, 38354 packages), because PKG_DBDIR
  is in the root.
- Limits of the trace: dirfd-relative paths (pkg's ~20000, certctl's 513)
  are not resolved by kdump; that they land in the root rests on the source
  (openat on rootfd) and on the host hashes and the find sweep.

== Conclusion ==

Package shell scripts run UNCHROOTED, as root, on the host, using the host's
binaries. On the 15.1 minimal set they read a few host configuration files and
write only into the root, because their text passes ${PKG_ROOTDIR} paths. Lua
package scripts: none in this set. Unsandboxed triggers are deferred, not run.

By the rule of Decision 7a, "if any script runs unchrooted against host paths,
that is raised before the template feature is enabled, not worked around".
Raised with Andy on 2026-11-16; the pkgbase source is not implemented until he
has answered.

/var/tmp/skep-trace7b (ktrace 57M, kdump, hashes, logs).
