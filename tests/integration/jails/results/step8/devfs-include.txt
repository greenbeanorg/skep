## What it means

Ruleset 6001 as amendment h defines it ("100 include 5", "200 path bpf*
unhide") resolves to ruleset 5's own non-include rule (`path pf unhide`)
and bpf: nothing hides anything, so the jail's devfs showed every host
device. The jail ran from 14:24:54 to about 14:27:45 UTC with only
/etc/rc and dhclient in it; nothing else ran inside it, and nothing was
tried with the devices. Not tested, on purpose: what the jail's root
could have done with them. securelevel 2 and the jail's missing
PRIV_KMEM/PRIV_IO privileges stop writes to disks and kernel memory, but
reads of the raw host disk (da0, root:operator 0640; the jail's root is
uid 0) are likely possible. Ruleset 5 jails (step 7) were never
affected: their /dev holds only fd null pts random stderr stdin stdout
urandom zero zfs.

Clean-up: n8dhcp stopped and deleted (dataset destroyed, epair gone),
ruleset 6001 removed with `devfs rule -s 6001 delset`, 57d74bb redeployed
so no build with this ruleset runs on hearst.
