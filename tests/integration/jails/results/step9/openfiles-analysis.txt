# Conclusion
# (The awk errors above are in the kqueue column of my listing only; the
# other columns are right.)
# - RACCT's openfiles counts each process's descriptor-table size, not
#   its open descriptors. The first table (20 slots) is not charged; when
#   a process first uses descriptor 20 its table grows and it is charged
#   40, at descriptor 64 it is charged 128, at 128 it is charged 256; the
#   charge never shrinks while the process lives. Idle, the jail is
#   charged 40 for cron, which has 5 descriptors open.
# - FreeBSD's tail(1) opens files through a Capsicum helper process
#   (casper, "tail: system.fileargs"), and that process's table is
#   charged too (128 at n=59, with only descriptors up to 6 open).
# - So at n=58 the jail is charged 120 (cron 40, tail 40, helper 40), at
#   n=59 it is 208 (the helper grew to 128), and at n=60 tail needs
#   descriptor 64, a 128-slot table: 40 + 128 + 128 = 296 > 256, refused
#   ("kqueue: Too many open files"). In the 300-file run of
#   maxproc-openfiles-quota.txt, 59 opens succeeded for the same reason.
#   Nothing else held ~200 open files.
# - For the docs: open_files is a budget of descriptor-table slots across
#   every process in the jail, rounded up in steps per process; size it
#   well above the descriptors the jail's programs keep open.
