## Findings

Held as specified (Decision 10):
- `ifconfig epair create` gives epair0a/epair0b; the host end takes the
  `skep:` description and joins bridge0 (bridge0's settings unchanged,
  only its member list); the jail end is renamed on the host to a stable
  name (`sjprobe8n0`, under IFNAMSIZ), given a fixed locally administered
  MAC, and moved in by jail(8)'s `vnet.interface`. Inside, the jail sees
  only lo0 and that name; it is no longer visible on the host.
- `jail -r` returns the jail end to the host under its stable name;
  destroying the host end destroys both ends and removes the bridge
  member. Nothing is left (no epair, no member, no dataset).
- The host end gets no address: IPv6 is IFDISABLED on epair0a, bridge0,
  and vtnet1 (hearst has no IPv6 configured), and IPv4 is never set.

NOT buildable as written:
- **DHCP, the default addressing, fails**: `dhclient` needs `/dev/bpf`,
  and devfs ruleset 5 (`devfsrules_jail_vnet`, fixed by Decision 9)
  hides it: "Can't find free bpf ... failed to start dhclient". rc then
  waits 30 s for a default route. Ruleset 5 on 15.1 is includes 1-4 plus
  `path pf unhide` only. Static addressing would work with ruleset 5, but
  the approved static range was not filled in ("<range>"), so no IPv4
  check (internet, isolation, SSH from merrick, reach to 10.79.20.170)
  could run.

Not run (needs an IPv4 address): everything above the link layer.
From the jail with IPv6 enabled on its own end (a tenant can do this):
only its own link-local answered ff02::1; nothing on VLAN 60 and no
hearst address answered.

## Options (for Andy)

A. A Skep devfs ruleset for DHCP jails: ruleset 5 plus `path 'bpf*'
   unhide`, used only for jails with `dhcp` addressing; static jails keep
   ruleset 5. bpf in a VNET jail sees only the jail's own interfaces
   (what the bridge delivers to its port: broadcast, multicast, flooded
   unknown unicast, its own traffic) and can write arbitrary frames on
   its epair, which is what a VM can do on its tap; amendment f already
   accepts spoofing on the epair. How the ruleset gets into the kernel:
   A1. The agent adds it at start under a fixed number with
       `devfs rule -s N add ...` (runtime, no file), checks its content
       before every start, and refuses (`devfs_ruleset_conflict`) if N
       exists with other rules. RECOMMENDED: no host file to manage,
       verified every start.
   A2. The operator installs it (`/etc/devfs.rules`, `devfs_rulesets` in
       rc.conf); Skep only checks it, as for if_epair.
B. Static addressing only for now (ruleset 5, no bpf). Needs a range on
   VLAN 60 outside the Kea pool for hearst; DHCP becomes a follow-up.
C. bpf for every jail (A without the per-jail switch). Simplest; gives
   static jails sniffing and frame injection they do not need.
