# Workaround and manual bhyve test on hearst (no Skep involved), 2026-11-14

Approved by Andy. hearst: FreeBSD 15.1-RELEASE-p6, booted 11:06 local
(reboot 1 of 2, after the KVM emulation failure of the first start).

## APIC virtual interrupt delivery off (live and persistent)

    kenv hw.vmm.vmx.cap.virtual_interrupt_delivery=0
    kldunload vmm && kldload vmm
    echo 'hw.vmm.vmx.cap.virtual_interrupt_delivery="0"' >> /boot/loader.conf; sync

Result:
    hw.vmm.vmx.cap.virtual_interrupt_delivery: 0     (was 1)
    hw.vmm.vmx.cap.posted_interrupts: 0              (was 1)
/boot/loader.conf now:
    vmm_load="YES"
    nmdm_load="YES"
    vfs.zfs.arc.max="1073741824"
    hw.vmm.vmx.cap.virtual_interrupt_delivery="0"
Undo: kenv -u the variable, reload vmm, delete the loader.conf line.

## Step 1: vmm instance without a vCPU run: passed
    bhyvectl --vm=m6probe --create   -> /dev/vmm/m6probe (crw------- root wheel)
    bhyvectl --vm=m6probe --destroy  -> /dev/vmm gone

## Step 2: first VMLAUNCH, plain bhyve: passed
    timeout 90 bhyve -c 1 -m 256M -H -A -u \
      -l bootrom,/usr/local/share/edk2-bhyve/BHYVE_UEFI.fd \
      -s 0,hostbridge -s 31,lpc \
      -s 3,ahci-cd,/home/aba/skep-m6/media/FreeBSD-15.1-RELEASE-amd64-disc1.iso,ro \
      -l com1,/dev/nmdm-m6probe.1A m6probe
Console read from /dev/nmdm-m6probe.1B (stty raw -echo clocal) for 60 s:
7875 bytes: UEFI firmware, the FreeBSD loader, the installer's boot menu,
and the 15.1-RELEASE kernel booting with "Hypervisor: Origin = bhyve".
bhyve's own output: "Unhandled ps2 mouse command 0xe1" (harmless).
merrick pinged hearst once a second throughout: 100 sent, 100 received,
0% packet loss.

## Step 3: cleanup: passed
    bhyvectl --vm=m6probe --force-poweroff  -> bhyve exited
    bhyvectl --vm=m6probe --destroy         -> /dev/vmm and /dev/nmdm* gone
Caps still 0; uptime 14 min (no reboot).
