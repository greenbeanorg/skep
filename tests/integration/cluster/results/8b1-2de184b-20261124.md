### Case 5: the prompt cannot work as written

With smith and langrishe as the only voters, stopping langrishe leaves no quorum (ADR 0013 A4: "no changes while one node is down"), so join step 1 cannot commit and star cannot become a non-voter. The build did the safe thing: no leader answered, so the join was known not to be applied and star's one-node state was put back. The case "one member stopped: the joiner stays a working non-voter, health names the stopped member, promotion follows its return" needs a cluster that keeps quorum with one member down (three voters and a fourth host). It is **tested in-process only** (`TestPromotionWaitsForAStoppedMember`: three voters, one stopped, a fourth node joins). Options are in the run's stop report.
