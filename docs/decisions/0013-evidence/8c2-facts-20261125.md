  `skep-api admin create --username NAME` as the skep account, interactive
  (`internal/setup/apply.go` `(*Applier).adminCreate`, `Cmd{Interactive:
  true}`), and skep-api asks for the password on `/dev/tty`. The lab runs

- remove's purge question: `cmd/skep-setup/remove.go` `runRemove` asks
  `e.confirm(...)` for `-purge-data` even with `-yes`; `askYes` reads one

## F2. `skep-api admin list --import-state` and `admin import-users`

- Both take `-config`, `-data-dir`, `-dev`, `-cluster-socket`
  (`cmd/skep-api/local.go` `newLocalFlags`); run as root they drop to the
  owner of the state directory first (`(*localFlags).prepare`,
  `dropToStateOwner`). Exit codes: 0 on success, otherwise the program's
  error exit (1 for a returned error, `cmd/skep-api/main.go`).
- `admin list --import-state` (`cmd/skep-api/importusers.go:160`
  `adminList`): opens `api.db` **read-only** (`mode=ro`), never migrates,
  prints the one word of `cluster_copy.import_state`. No `api.db`: error
  "there is no api.db at PATH" (exit 1). An `api.db` at schema 0005 has no
  `cluster_copy` table: error "read PATH: … no such table" (exit 1); this
  is the join's blind spot (the join goes on when the state cannot be
  read, amendment 4 point 6).
- `admin import-users` (`importusers.go:40` `adminImportUsers`): opens the
  database with `openDatabase` (`cmd/skep-api/main.go:306`), which **runs
  every pending migration**, so on schema 0005 it applies `api/0006` itself
  (as the skep account), then imports. On no `api.db` it creates and
  migrates one. Migration `api/0006` therefore runs at the service's start
  and at any local command that opens the database with `openDatabase`
  (every `admin` command except `exists` and `list`).

## F3. Status, the leader and the build

- `store.Stats` (`internal/cluster/store/store.go:105`) has `LeaderID`

  -version` is parsed by `runServe`'s flags and is not a version command.
  The agent and the API print `skep-agent 0.1.0 (commit 37ccf1e, …)` with
  `-version` (`internal/setup/upgrade.go` `versionLineRE`): a different
  shape, so setup needs its own pattern for skep-cluster.

## F4. `skep-cluster init` run again after a partial state

`cmd/skep-cluster/init.go:107` `runInit`, part 1 as root: `CheckOldLayout`,
then `store.Exists(layout.State(dir))` refuses an initialised host, then
the account, the name, the agent's node ID, `prepareDataDir`,
`clusterconf.Write`; part 2 as the account: `service.CreateCluster`.

- Data directory only (no key, no store): `prepareDataDir` accepts an
  existing directory owned by the account with mode 0700 (refuses another
  owner or mode, "nothing was changed"); init then goes on normally.
- `cluster.json` and no store: `clusterconf.Write`
  (`internal/cluster/clusterconf/clusterconf.go:149`) writes a temporary
  file and **renames it over** the existing one: it is replaced with the
  new node ID and name; init goes on.
- Key and no store: `CreateCluster` (`internal/cluster/service/wipe.go:32`)
  loads the existing key with `nodekey.LoadRepair` (for the same node ID)
  and makes the store; a key that does not load refuses with "remove
  key.pem and cert.pem as root to start over". A failed bootstrap removes
  the half-made state directory (`fail`), so the next attempt starts
  clean.
- So "init" is safe to run again after each partial state; an initialised
  host (a store) is always refused.

## F5. Errors and time limits on the API side

- `auth.NoQuorum(outcome, message)` (`internal/auth/types.go:101`) returns
  `*models.Error{Code: "no_quorum", Details: {"outcome": outcome}}`;
  outcomes `not_written`, `unknown`, `written_not_synced` (lines 95–97).
- `statusForAuthCode` (`internal/api/session.go:29`) maps `no_quorum` and
  `users_import_pending` to 503, `too_many_users` to 409; `h.fail`
  (line 48) writes a mapped `*models.Error` with its details
  (`WriteErrorDetails`), anything else through `httpkit.Fail`.
- `decodeBody` (`internal/api/session.go:164`) is strict: Content-Type
  must be `application/json` (415 otherwise), unknown fields refused, no
  data after the object, at most 64 KiB (`maxBodyBytes`).
- skep-api's HTTP server (`cmd/skep-api/main.go` `serve`, line 367):
  `ReadHeaderTimeout` and `ReadTimeout` = `read_timeout` (default 15 s),
  `WriteTimeout` = `write_timeout` (default **60 s**,
  `internal/config/api.go:274`), `IdleTimeout` twice that. The socket's
  remove may take up to `localapi.RemoveTimeout` = 60 s, so the default
  write limit would cut its answer: the remove endpoint must extend its own
  write deadline (Go's `http.ResponseController.SetWriteDeadline`).
- The cluster socket's own `decodeBody`
  (`internal/cluster/localapi/handler.go:464`) is strict too
  (`DisallowUnknownFields`, one object).

## F6. How skep-api reaches the cluster socket

- `internal/cluster/userapi` holds the users-read and users-write messages
  and a client; it imports the standard library, `clusterstate` and
  `pkg/models` (`go list -deps ./internal/cluster/userapi`: only
  `clusterstate`, `pkg/models`, `pkg/version` from this module).
  `localapi` aliases its types (`internal/cluster/localapi/users.go`).
  skep-api builds one `userapi.NewClient(cfg.ClusterSocket)`
  (`cmd/skep-api/main.go:193`).
- `go list -deps ./cmd/skep-api | grep -c hashicorp/raft` = 0;
  `go list -deps ./cmd/skep-setup | grep -c hashicorp/raft` = 0 (on
  7959456).

## F7. rcorder and a REQUIRE without a running provider

Run on smith (FreeBSD 15.1, read-only, two throw-away scripts in a temp
directory):

- A REQUIRE on a service whose script exists is ordered after it whatever
  its `_enable` (rcorder reads only the PROVIDE/REQUIRE lines; a disabled
  service's script still runs and returns at once).
- A REQUIRE whose provider's script is missing: rcorder prints
  "requirement `b' in file `a' has no providers.", exits 1, and **still
  lists `a`**. `/etc/rc` (lines 103 and 123) runs
  ``files=`rcorder … 2>/dev/null` `` and uses the list, not the exit
  status.
- So `REQUIRE: LOGIN skep_agent skep_cluster` in skep_api's script neither
  stops skep_api when skep_cluster is disabled nor when its script is
  missing (D4 holds).

## F8. `os.RemoveAll` and symbolic links

go.mod says `go 1.26.0`; merrick builds with go1.27.4. `os.RemoveAll` on
unix is `removeall_at.go` (`//go:build unix || …`): `removeAllFrom` first
tries `unlinkat` on the entry (a symbolic link is removed as a link), and
opens a directory to recurse into with `openat(…, O_NOFOLLOW|O_DIRECTORY)`
(`os/root_unix.go` `rootOpenDir`). A symbolic link inside the tree, or as
the path itself, is unlinked and never followed. The parents of the path
(`/var/db/skep`) are checked to be root's by `setup.CheckDataDir` before
any purge.
